wolf

A compiled systems language. Pre-alpha; the surface still moves.

wolf install playground the book docs spec changelog

Memory lives in regions the compiler infers, so a program carries no lifetime annotations. Allocation goes through arenas by default. A region moves between tasks instead of being shared, which is what keeps concurrent access safe, and the aliasing that falls out of that is information the optimizer gets to use. Arithmetic is checked in every profile, including release.

fn fill(n: int) -> List[int] {
    var xs = List[int]()           // lands in the caller's current region
    for i in 0..n { (mut xs).push(i) }
    xs
}

fn main() -> !int {
    var total = 0
    region tmp {
        let xs = fill(100)         // allocated in tmp [mem.region.create.3]
        for x in xs { total += x }
    }                              // wholesale free [mem.region.intra.2]
    if total == 4950 { 0 } else { 1 }
}

That is corpus/memory/region_ambient_ok.lu, verbatim below its header. The callee allocates into the caller's region, so the list lives in tmp and dies with it, and the bracketed names in the comments are the specification clauses the program is pinned to. Run it in the browser, along with thirty-odd other programs from the same corpus.

What runs today

v__WOLF_VERSION__ is tagged, still under the codename wolfgang. wolf build and wolf run compile .lu source to native machine code through the compiler's own backend, with no LLVM in the loop. wolf build --release emits textual LLVM IR and hands it to the system clang — no LLVM libraries linked, no new dependencies. Both tiers produce the same verdict and the same output on every corpus program they both execute, and CI holds a floor under how many that is, so the comparison cannot quietly shrink to nothing. A binary never claims a release it is not: wolf --version built anywhere but the tag answers with the build's commit.

The first chapter compiles. Chapter 1 of the book asks a string for a number twice, row.to_int() in the cold open and again in exercise 1-10, and until this release the compiler refused that call: the first non-trivial string method a learner met was also the first program that would not build. At v__WOLF_VERSION__ str.to_int() -> int ! {NotAnInt} is in the builtin set on both tiers, spelled the way the reference interpreter has always spelled it. Text it cannot read is a value your program can branch on rather than a trap: the surrounding whitespace is ignored, an optionally signed run of ASCII digits that fits int is the number, and everything else — the empty string, a word, an interior space, a fraction, a radix prefix, a lone sign — is the NotAnInt row. When a method really is outside the set the refusal names it now, this `str` method, `to_int`, is outside the builtin set, where it used to hand back a byte span and leave you counting.

And the syscall goes first. At the other end of the language, a program that reads a socket the kernel has already made ready makes the read and waits for nothing. Every parking call in the net family used to go to the reactor thread first — a waiter cell, a lock handshake, a kevent to arm it, a kevent to wake it, a condvar, two context switches — and only then make the syscall, on a socket the program's own net_wait had just reported ready. lobo, the web server this project is writing in wolf, paid that round trip three times per request. The same lobo source, untouched, was built against the v0.2.6 pin and against this release and run on one macOS arm64 box in a single session six minutes apart: 53.3 µs per request before and 21.2 after, 18,766 requests a second to 47,162, and the share of the serving thread parked in a condvar down from 40.7% to 1.1%. The wolf-reactor thread never started at all in the second run, because the reactor is lazy and a serving loop that never parks never asks for one. Read that pair as a ratio rather than a score: other lanes were working on the machine, the benchmark tool refused both sets under its own quiet-rig rule, and neither is an entry in lobo's ledger. What the two share is the box, the hour and the load. No row a program can observe moved; the cost did.

Three smaller changes ride along. TCP_NODELAY is on for every TCP stream the runtime hands out, so the ordinary shape — a head, then a body, two writes with a small second one — no longer stalls 40 ms behind the peer's delayed ACK, and net_nodelay sets it either way. net_writev sends the head and the body as one gathered write. fs_fstat answers kind, size and modification time from a single metadata read on an open handle, where a static-file server used to pay four separate path stats for the same three facts. Every call that existed at v0.2.7 keeps its signature and its error rows, so a program written against it behaves the same way here — as one written against v0.2.5 still does, since v0.2.6 made a hand that loses an accept race come back inside the budget its net_deadline armed instead of parking in the kernel until the next connection arrived, which on a quiet server was never.

There is a second implementation. lupin is a reference interpreter written against the same specification, sharing no code with the compiler; the two are compared program by program through a published observation protocol. Neither is allowed to disagree with the other in silence. wolf --version names the lupin release the compiler was differentially tested against, and since v0.2.7 a CI job fetches that lupin by digest and runs the comparison on a runner, so the line cannot go stale somewhere only a laptop would notice. The playground on this site runs that interpreter, compiled to WebAssembly.

The performance goal the project set for itself, beating naive clang -O3 across a kernel suite, was declared met on 2026-08-24: three consecutive nightly runs of the benchmark ritual held the suite geometric mean above that baseline — 1.099, 1.066, 1.080 — with two documented exceptions renounced in writing. The suite once measured 0.191 of the same baseline, and the measurements that refuted the goal along the way still ship with the code, beside the protocol for reproducing all of them.

There are no macros; compile-time evaluation and reflection are the metaprogramming tier. Packages are declarative — reading a dependency graph never executes anything — and there is no hosted registry.

Getting it

git clone https://github.com/wolffe-lang/wolf-lang
cd wolf-lang
cargo build --release -p wolf_driver
./target/release/wolf run corpus/hello.lu

That prints hello, wolf. To put the toolchain on your path instead, cargo xtask install copies both artifacts to ~/.local/bin: the wolf binary and the runtime archive it links programs against. The binary cannot link anything without the archive beside it, which is why the install step exists.

Or let a package manager do it (a Homebrew tap on macOS and linux, five packages on the AUR, all of them the project's own), or take a published archive instead of building one: installing wolf has both, and the per-platform story, including Windows, where the compiler builds and runs native programs once Visual Studio Build Tools is installed beside it — tasks, channels and signals included, with five named refusals left and each of the five measured rather than described. That page quotes what a machine without Build Tools sees, and every Windows sentence on it is asserted against the published archive by a job on a Windows runner.

The toolchain pin is Rust 1.97.1, recorded in rust-toolchain.toml, and rustup honors it on the first cargo invocation. There are no build scripts anywhere in the wolf ecosystem. CI builds and tests linux x86-64, macOS aarch64 and windows x86-64, which are also the three hosts native code generation serves; linux aarch64 is tier-1 in the matrix without a CI runner or a backend behind it yet, so its archive runs programs on the checked tier rather than compiling them. Tagged builds upload an archive per tier-1 host to the releases page — four at v__WOLF_VERSION__, and a job in this site's own CI asks every one of those four URLs for a 200 on every change to this site. The packaging around them is a stub, so building from source is the path that is known to work.
