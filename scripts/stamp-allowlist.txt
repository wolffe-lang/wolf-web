# Every version PLACEHOLDER in the site's prose, classified:
#   <path under site/> <placeholder> <total> bound=<n> [audited-at-<project>=<version>]
#
# The version allowlist beside this file covers literals. A placeholder is
# exempt from it BY CONSTRUCTION — build.sh stamps it from the pin, so it can
# never fossilize — and that exemption is itself a hole. A sentence like
# "__WOLF_VERSION__ is a release about writing servers" is true of exactly one
# release. The stamp moves, the sentence renders with a new number, and it is
# now false with nothing anywhere to notice. ww15 found two of those and had to
# rewrite them by hand; this file is what stops the next one.
#
# `bound=<n>` is how many of the file's occurrences are RELEASE-BOUND: true
# only of the release the stamp names. The rest are timeless — a download URL,
# a `wolf --version` transcript's shape, "this is version X" — and stay true
# whatever gets stamped into them. A total that drifts fails, so a new
# placeholder cannot appear unclassified; and when `bound` is more than zero
# the entry carries an `audited-at`, which the pin bump moves past exactly the
# way it does for a literal. Re-read the bound sentences, then re-stamp.
#
# The clock is the placeholder's own: __WOLF_VERSION__ entries are audited at
# wolf, __LUPIN_VERSION__ entries at lupin. That is not decoration. The pin-lag
# sentence on /install/ and /play/ reads "lupin __LUPIN_VERSION__ was released
# against v0.2.4" — the literal there rides the WOLF clock, so a lupin-only
# release would leave the sentence unread while making it false. The bound
# __LUPIN_VERSION__ entry is what catches that one.
#
# ww20 is the first bump where both clocks moved at once, so all six entries
# reddened together and all ten bound sentences were re-read. Four were false
# and all four were the same mistake: a paragraph telling the LAST release's
# story under this release's stamp. Three were the front page's (the first
# chapter, the syscall-first accept, the three net calls) and one was /spec/'s
# copy of the third. The rewrite is per release, not per stamp.
#
# ww21 moves lupin alone, so the two __LUPIN_VERSION__ entries reddened and the
# four __WOLF_VERSION__ ones did not. Both bound sentences are the pin-lag
# paragraph, one per page, and both were false in the same way: they named the
# revision the LAST interpreter release was built to. The gap they state is
# still one release, because the new revision is still trunk past v0.2.8 — what
# moved is the sha and the distance, and the distance is a stamp.
#
# ww23 moves lupin alone again, so the same two __LUPIN_VERSION__ entries
# reddened and the four __WOLF_VERSION__ ones did not. Both bound sentences are
# the pin-lag paragraph and both were false in the same way, but for the
# opposite reason to ww21's: the gap they stated has CLOSED. lupin 0.1.31 was
# built at the v0.2.9 tag itself, so both paragraphs are rewritten for a gap of
# zero, and the distance stamp they carried is gone from both pages because
# there is no distance to state.
#
# Neither this file nor the literal allowlist beside it can see a sentence
# that carries no version and no placeholder, and the pin-lag prose is
# written three times across /install/ and /play/ — one of those three
# ("one release behind the compiler's at these pins") has neither. Both
# audits were green over it while it was stale. The windows job's pin-lag
# step counts the gap and holds the phrase on both pages, which is where
# that third sentence is covered; it is not covered here.
#
# ww24 moves WOLF alone, so the four __WOLF_VERSION__ entries reddened and the
# two __LUPIN_VERSION__ ones held. Those four carry SEVEN release-bound
# sentences between them and all seven were re-read. Three were rewritten and
# four stood.
#
# Rewritten, and all three the same mistake this file exists to catch — a
# sentence telling v0.2.9's story under v0.2.10's stamp: the front page's
# release paragraph (the layout rule, the `parse` row and `char + str` are
# gone, and `match` as a switch with range arms, E0416 and W0601 are in their
# place); /spec/'s 01-grammar status line, which told the same layout story and
# now tells `[gram.pat.range]`; and /play/'s "answers differently here from a
# <stamp> you download today", which was true of a zero gap and had to say what
# a gap of one means instead.
#
# Stood: the front page's "is tagged, still under the codename wolfgang" and
# its four-archives sentence (still four at this tag, and the windows job
# fetches all four), and /install/'s page-wide "this page describes that
# release and no other" and its own four-archives sentence.
#
# Two totals move DOWN, and one of them is a check changing hands rather than
# a check being dropped. The front page loses one occurrence (6 -> 5, bound
# 4 -> 3) because its three release paragraphs became three paragraphs and a
# code block. /install/ loses one (11 -> 10, bound 3 -> 2) because the pin-lag
# sentence no longer names the compiler's version at all: at a gap of one it
# says "the tag of the release before this one". What holds it now is the
# windows job's phrase check, which is page-wide and reads the two gitlinks
# rather than the prose — a stronger gate than this file's, not a weaker one.
# The trade belongs written down where the count drops.
