# Deliberate version literals in the site's own prose, one line each:
#   <path under site/> <literal> <count> audited-at-<project>=<pinned version>
#
# Current-version claims never belong here — they are written as
# __WOLF_VERSION__ / __LUPIN_VERSION__ and stamped by build.sh from the
# pins. This list is for history: sentences that name an old version on
# purpose. check-version-prose.py fails the build when a literal is
# missing from this list, when its count drifts, or when the named pin
# moves past an entry's audited-at — so every pin bump forces these
# sentences to be re-read rather than trusted.
#
# The audit column names ITS OWN CLOCK. `audited-at-wolf=` is re-read when
# the compiler tags; `audited-at-lupin=` when the interpreter does. Through
# ww14 there was one clock, wolf's, so a lupin-only bump re-read nothing and
# the lupin sentences below were covered by hand twice (ww11, ww14). That was
# wolf-web#8's second half; its first was a regex that saw only `v`-prefixed
# literals, which is why the lupin entries here were spelled `v0.1.22` on
# purpose. Both are fixed, so they are spelled the way the site spells a
# lupin release everywhere else — bare.
#
# A version-shaped number that is not a wolf or lupin claim still gets a
# line: the toolchain pin below is such a number, and it was invisible to
# this file until the regex widened. It rides the clock of the checkout that
# records it.
#
# BOTH clocks moved at ww20 for the first time since ww15 — wolf 0.2.8 -> 0.2.9
# and lupin 0.1.28 -> 0.1.29 in one bump — so every entry below reddened at
# once and every one was re-read. Two sentences were false. /spec/'s
# "at (the wolf stamp) it states when the syscall happens" was v0.2.8's os
# document under v0.2.9's stamp and names v0.2.8 now; the front page's three
# release-bound paragraphs told v0.2.8's story and were rewritten for this
# release's three rulings.
#
# ww21 moves the lupin clock alone (0.1.29 -> 0.1.30) and the wolf entries hold
# untouched, which is what a per-clock audit column is for. The six lupin
# entries were re-read: /play/'s five historical ones all held — the
# `stdout_inline` story through 0.1.22 and 0.1.23, the net calls landing at
# 0.1.28, and the byte cast ladder that 0.1.25 closed and that still exits 0
# through the module this build publishes — and /install/'s freshness pair was
# read live and moved. Both channels had already shipped 0.1.30 by the time the
# pin landed here, which is the opposite of ww20's reading and exactly why it
# is a literal.
#
# ww23 moves the lupin clock alone again (0.1.30 -> 0.1.31) and the wolf entries
# hold untouched. The five historical /play/ entries were re-read against the
# module this build publishes: 0.1.22 and 0.1.23 are a `stdout_inline` that was
# null on every trapping program and the defer disagreement that hid behind it,
# neither touched by this release; 0.1.24 and 0.1.25 are the byte cast ladder,
# and `typecheck/byte_casts.lu` still exits 0 in the census, so "it has stayed
# closed" is still true; 0.1.28 is the release that put the three net calls in
# the interpreter, and they are still in it. /install/'s freshness pair moved
# and was read live, not inferred: the tap's `lupin` formula builds tag v0.1.31
# at revision e9c55b4 and the AUR has `lupin` and `lupin-bin` at 0.1.31-1, while
# both compiler packages sit at 0.2.9-1 and the tap's `wolf` builds v0.2.9. Every
# channel agrees, which is the second bump running that it has.
#
# One wolf entry LEAVES rather than being re-read. /install/'s `v0.2.8` was the
# tag the pin-lag paragraph named as the newest release the interpreter had
# read; at a gap of zero there is no such tag to name and the sentence is gone,
# so the entry goes with it. An allowlist line whose sentence has been deleted
# is a count that can only drift.
#
# ww24 moves the WOLF clock alone (0.2.9 -> 0.2.10), the mirror image of the
# three passes before it: the eighteen wolf entries here — twenty-eight literal
# mentions between them — reddened together, and the six lupin ones held
# untouched. All eighteen were re-read and all eighteen stood, the freshness
# pair by moving with the release rather than behind it (see below).
# /spec/'s six historical mentions are about 10-types' byte, 11-os's
# socket sections and 07-schedule-points' anchors; the documents this release
# touches are 01, 02, 03 and 10, and none of the six sentences is about what
# moved in them. /install/'s platform history (v0.2.1 through v0.2.6) is a
# Windows story and this is not a platform release. The front page's `v0.2.7`
# still names the release that put the differential comparison on a runner, and
# `1.97.1` is still what the pinned `rust-toolchain.toml` says — read off the
# checkout at the tag rather than remembered. /play/'s `v0.2.4` and `v0.2.8`
# are the byte's release and the three net witnesses', both unmoved.
#
# The freshness pair moves WITH the release for the first time, which is worth
# a line because it is the outcome this entry was written to be unable to
# assume. It was read live at the bump: the tap's `wolf` formula builds tag
# v0.2.10 at revision 662b14c and its `lupin` builds v0.1.31, and the AUR
# carries `wolf-lang` and `wolf-lang-bin` at 0.2.10-1 beside `lupin` and
# `lupin-bin` at 0.1.31-1. The packaging lane closed the doors the same day the
# tag went up. Had it not, this entry would have said so, which is the whole
# reason it is a literal and not a stamp.
#
# A version literal here need not be a claim about wolf or lupin themselves.
# The package-manager entries below are claims about what a THIRD PARTY has
# published — the AUR's `wolf-lang`/`lupin` and the tap's formulae — and they
# are literals on purpose rather than stamps. A stamped freshness claim would
# re-render with the new number at every bump and assert, without anyone
# looking, that a packager had already pushed. As literals they go red at the
# bump and someone re-reads the live channel, which is the only way to know.
